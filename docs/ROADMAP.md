# 모래 실험실 로드맵

기간은 1인 개발 기준의 대략적인 추정치입니다. 순서와 범위는 자유롭게 고쳐 주세요.

## 1. 목표

- **핵심 경험:** 물질을 만나게 하고 → 관찰하고 → 왜 그런지 이해한다.
- **차별점:** 일반적인 샌드박스 게임은 "그럴듯해 보이는 것"이 목표입니다. 이 프로젝트는 **측정값을 이론과 비교할 수 있는 것**을 목표로 합니다.
- **최종 형태:** 다른 웹사이트에 태그 한 줄로 넣을 수 있는 기능. 단독 게임으로도 동작합니다.

**현재 우선순위: 화학.** 물리 강화(아래 2단계)는 뒤로 미루고 화학 시스템(3단계)을 먼저 진행합니다.

### 검증된 것 (`tests/tests.html`, 56개)

- 반응이 일어나야 하는 189쌍은 일어나고, 일어나면 안 되는 44쌍(구리+염산, 금+진한 질산, BTB+물, 수소+공기(불씨 없음), 소금+소금물, 브로민수+메테인, 익은 간+과산화수소 등)은 일어나지 않음
- 핵분열: 큰 농축 우라늄 덩어리는 폭발하고 작은 덩어리는 안전, 플루토늄은 더 작은 양으로 폭발, 천연 우라늄은 반응 없음, 물속에서는 녹을 뿐 폭발하지 않음, 제어봉이 연쇄 반응을 막음
- 폴로늄은 붕괴열로 스스로 달아오르고 우라늄은 그대로, 세슘+물·산수소·쇳물+물은 폭발하고 폭발이 공을 밀어냄
- 설탕은 베네딕트 반응을 하지 않고, 탄산나트륨·탄산칼륨은 800°C에서도 분해되지 않음
- 화면에 나오는 모든 일반 규칙 반응식 약 12,500개와 특수 반응 표의 반응식 130개의 원자 수 균형이 맞음
- 화학 정원의 관이 위로 자라고, 핫 아이스가 한꺼번에 굳으며 데워지고, 효모는 30°C에서만 발효하고, 아연과 닿은 철은 녹슬지 않음
- 철·알루미늄은 진한 질산·황산에서 상온에서는 부동태로 멈추고 가열하면 녹음
- 지시약마다 변색 범위가 다름(BTB는 탄산수에서 노랑, 페놀프탈레인은 pH 8.2 위에서만 분홍 등 12건)
- 소금물은 -21°C, 염화칼슘 용액은 -50°C까지 얼지 않고, 얼음+소금 실험이 영하 10~21°C까지 내려감
- 녹는점·끓는점 18건이 기준 온도 위아래에서 올바르게 변함
- 용광로에서 납 → 알루미늄 → 구리 → 철 순서로 녹음
- 자유낙하 측정 g가 설정값과 0.1% 안에서 일치, 금속 열전도 에너지 보존, 물의 끓는 시간이 잠열 계산과 일치
- 예전에 가끔 실패하던 테스트 3개의 원인을 고침: 재가 나무를 덮어 모닥불이 꺼지던 것(재는 공기가 통하고 상승 기류에 날림), 금속이 산과 1:1로 반응해 반응성 차이가 안 보이던 것, 수소 혼합 기체에서 불꽃이 번지지 않던 것. 연속 3회 모두 통과

## 3. 단계별 계획

### 1단계: 프로토타입 다듬기 (2~3주)

직접 만져 보면서 재미와 조작감을 먼저 잡는 단계입니다.

- [ ] 터치 조작 개선: 두 손가락 확대·이동, 붓 모양 선택, 실행 취소
- [ ] 소리 효과 (끓는 소리, 반응음), 켜고 끄기
- [ ] 저장 슬롯과 공유 링크 (이미 있는 `save()`/`restore()` 활용)
- [ ] 온도계 여러 개를 동시에 비교
- [ ] 측정 데이터 CSV 내보내기, 그래프 표 보기
- [ ] 저사양 기기 측정과 자동 해상도 조절

**완료 기준:** 저가형 휴대폰에서 60fps에 가깝게 동작하고, 처음 쓰는 사람이 설명 없이 반응 3개를 발견한다.

### 2단계: 물리 엔진 강화 (2~3개월)

"물리 법칙을 제대로 확인"하는 목표의 핵심입니다. 엔진의 큰 변경은 이 단계에 모읍니다.

- [ ] **칸 단위 질량 도입:** 칸마다 질량을 저장해 질량 보존 법칙을 만족
- [ ] **압력장:** 기체 상태 방정식(PV=nRT), 파스칼 원리, 수압, 밀폐 용기 폭발
- [ ] **유체 개선:** 칸 단위 속도장 도입으로 소용돌이와 물결 표현
- [ ] **강체 확장:** 공 외에 상자·막대, 회전, 경사면, 도르래, 용수철
- [ ] **강체↔유체 양방향:** 공이 물을 밀어내고 물 튀김 발생, 나무 블록이 뜸
- [ ] **복사열:** 슈테판-볼츠만 법칙 기반
- [x] **전기 분해:** 물 → 수소 + 산소(2:1), 소금물, 도금, 정련, 합선
- [ ] **전기 회로:** 도체·저항·전지, 줄 열, 전압에 따른 반응 속도
- [ ] **성능:** 칸 수가 늘어나면 WebWorker → WebAssembly → WebGPU 순으로 이전

**물리 실험 모드 추가 목록**

| 주제 | 비교할 법칙 |
|---|---|
| 포물선 운동 | 사거리 = v²sin2θ/g |
| 단진자 | T = 2π√(L/g) |
| 용수철 | F = -kx, 에너지 보존 |
| 경사면 | 마찰 계수 측정 |
| 탄성·비탄성 충돌 | 운동량 보존 |
| 뉴턴 냉각 | 지수 감소 곡선 |
| 보일·샤를 법칙 | PV, V/T 일정 |
| 파스칼·아르키메데스 | 수압, 부력 |
| 비중 측정 | 부력으로 물질 판별 |

**완료 기준:** 각 실험의 측정값이 이론값과 정해 둔 오차(예: 5%) 안에 들어오고, 이를 자동 테스트로 계속 확인한다.

### 3단계: 화학 시스템 확장 (2~3개월)

- [x] **물질 확장:** 주기율표 전체, 금속 반응성 계열, 불꽃 반응 색, 앙금, 합금
- [x] **지시약 기초:** 페놀프탈레인, 리트머스 색 변화
- [ ] **몰 단위 반응:** 칸의 물질량을 사용해 화학 양론을 만족 (한계 반응물 개념)
- [ ] **용액 시스템:** 농도, 용해도 곡선, 포화와 재결정, 끓는점 아래의 증발
- [x] **pH 기초:** 물질별 pH 값, 지시약마다 다른 변색 범위, BTB 추가
- [ ] **pH 심화:** 농도에 따라 변하는 pH, 적정 실험
- [ ] **반응 속도:** 온도·농도·촉매 의존성 (아레니우스 식)
- [x] **착이온과 부동태 기초:** 구리·은-암모니아, 철-싸이오사이안산, 양쪽성 수산화물, 크로뮴산⇄다이크로뮴산, 철·알루미늄·크로뮴의 부동태
- [ ] **산화수:** 산화수별 생성물 전반(예: 철과 수증기 → Fe₃O₄)
- [ ] **물질 도감:** 물질별 설명·성질·출처 화면
- [ ] **데이터 검수:** 물성값과 반응식을 교사나 전공자가 확인하고 출처를 기록

**안전 원칙:** 실제로 위험한 물질의 제조법이나 구체적인 합성 조건은 넣지 않습니다. 시뮬레이션은 현상 관찰용이며, 실제 실험을 안내하지 않는다는 문구를 화면에 표시합니다. 특히 나트륨·산·염기 실험에는 "실제로 따라 하지 마세요" 안내를 넣습니다.

### 4단계: 게임 요소 (1~2개월)

- [ ] **발견 도감 완성:** 진행률, 숨은 반응 힌트
- [ ] **도전 과제:** "유리를 만들어라", "물을 쓰지 않고 불을 꺼라", "1kg 철 공의 낙하 시간을 예측하라"
- [ ] **예측 → 실험 → 비교:** 결과를 먼저 예상하게 한 뒤 실험으로 확인 (학습 효과가 큼)
- [ ] **장치 부품:** 스위치, 밸브, 센서, 펌프
- [ ] **만든 실험 공유:** 링크 또는 갤러리

### 5단계: 사이트 통합 (대상 사이트가 정해지면 1~2개월)

- [ ] 대상 사이트 기술 스택 확인 후 패키지 형태 결정
  - 일반 페이지: 지금의 `<script>` + `<sand-lab>` 태그
  - React·Vue 등: 얇은 래퍼 컴포넌트, npm 패키지
  - 격리가 필요하면: `iframe` + `postMessage`
- [ ] **계정 연동:** `storage`를 서버 API로 교체해 도감과 저장 파일 동기화
- [ ] **학습 기록 연동:** `sandlab:discover` 이벤트를 사이트의 진도·점수와 연결
- [ ] **교사 기능:** 특정 실험 배정, 재료 제한 옵션(`allowedMaterials`), 결과 제출
- [ ] **번들 크기 관리:** 물질·실험 데이터 분리 및 지연 로딩
- [ ] **다국어:** 문자열을 데이터 파일로 분리 (한국어·영어)
- [ ] **접근성:** 키보드 조작, 색각 대응 보기, 화면 낭독기용 상태 안내
- [ ] **콘텐츠 보안 정책(CSP) 확인:** 현재 동적 코드 실행은 쓰지 않음

## 4. 먼저 정해야 할 것

아래 결정에 따라 2단계 이후의 설계가 달라집니다.

1. **사용자가 누구인가요?** 초·중·고 또는 일반인에 따라 화학식 표시 수준과 도전 과제가 달라집니다.
2. **어떤 사이트에 들어가나요?** 기술 스택과 계정 시스템을 알면 5단계 형태가 정해집니다.
3. **학습 도구와 놀이 중 어느 쪽이 우선인가요?** 정확성과 화려함이 충돌할 때 기준이 됩니다. 현재는 정확성을 우선했습니다.
4. **이름과 시각 스타일은 어떻게 할까요?** 참고한 게임의 이름이나 그림을 그대로 쓰지 않도록, 자체 이름("모래 실험실"은 임시 이름)과 스타일이 필요합니다.

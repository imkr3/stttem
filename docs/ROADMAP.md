# 모래 실험실 로드맵

기간은 1인 개발 기준의 대략적인 추정치입니다. 순서와 범위는 자유롭게 고쳐 주세요.

## 1. 목표

- **핵심 경험:** 물질을 만나게 하고 → 관찰하고 → 왜 그런지 이해한다.
- **차별점:** 일반적인 샌드박스 게임은 "그럴듯해 보이는 것"이 목표입니다. 이 프로젝트는 **측정값을 이론과 비교할 수 있는 것**을 목표로 합니다.
- **최종 형태:** 다른 웹사이트에 태그 한 줄로 넣을 수 있는 기능. 단독 게임으로도 동작합니다.

**현재 우선순위: 화학.** 물리 강화(아래 2단계)는 뒤로 미루고 화학 시스템(3단계)을 먼저 진행합니다.

| **반응은 칸 2개 → 칸 2개** | 화학식은 균형이 맞지만, 칸 수로는 몰 비를 지키지 않고 물처럼 부수적인 생성물은 칸으로 안 나타날 때가 있음 | 3단계 |
| 농도는 2차 단계 | 칸마다 농도·pH·용해도가 있지만, 녹은 물질끼리 섞인 용액(예: 소금물 + 설탕물)은 칸이 따로 있음 | 3단계 |
| 복잡한 반응의 단순화 | 착이온은 구리·은-암모니아, 철-싸이오사이안산, 알루미늄·아연-수산화 이온만 있음. 산화수별 생성물 차이는 일부만 표현(산화성 산은 철(III)을 만듦) | 3단계 |
| 증발은 단순화 | 물·수용액·휘발성 액체가 끓는점 아래에서도 증발하지만(따뜻할수록 빠름), 증기는 공기 속으로 사라진다고 보고 습도는 다루지 않음 | 3단계 |
| 포화 단순화 | 다른 물질의 용액에 녹을 때는 녹은 양에 제한이 없음, 결정 한 칸 = 기준 농도 용액 두 칸 분량으로 고정 | 3단계 |
| 핵분열·붕괴는 개념 모형 | 임계 질량·중성자 값은 실제 핵물리 값이 아니라 관계를 보여 주는 값. 붕괴로 원소가 바뀌는 것(반감기)과 방사선 피폭은 다루지 않음. 핵융합 없음 | 유지 |
| 압력 없이 폭발을 흉내 냄 | 폭발은 정해진 반지름 안을 한 번에 밀어내는 방식이고 충격파가 전파되지 않음 | 2단계(압력장) |
| 한 칸 = 일정 부피이고 **질량이 보존되지 않음** | 물 1칸이 수증기 1칸이 됨 (실제 부피는 약 1,700배) | 2단계 |
| 압력은 공간 단위 | 닫힌 기체 공간마다 PV=nRT로 압력을 구하고 용기가 견디는 압력을 넘으면 터짐. 끓는점은 트루턴 규칙으로 어림한 클라우지우스-클라페이론 식이라 높은 압력에서 실제보다 조금 높음(5기압에서 물 166°C, 실제 약 152°C). 압력이 퍼지는 속도는 없음(닫힌 공간 안은 곧바로 같은 압력). 수압은 끓는점과 표시에만 쓰고 흐름에는 쓰지 않음 | 2단계 |
| 열전달 가속 사용 | 시간이 실제보다 빠름. 배율을 화면에 표시 중 | 유지 |
| 불이 번지는 규칙 단순화 | 현상 재현 수준이며 측정용이 아님 | 3단계 |

## 3. 단계별 계획

### 1단계: 프로토타입 다듬기 (2~3주)

- [x] 터치 조작 개선: 두 손가락 확대·이동(데스크톱은 Ctrl+휠), 실행 취소, 키보드 단축키(스페이스·[ ]·0)
- [x] 소리 효과(폭발·깨짐·불티·발견·장치 소리, Web Audio로 합성, 기본 꺼짐)
- [x] 저장 슬롯 3칸과 공유 코드(압축, `exportCode()`/`importCode()`)
- [x] 온도계 여러 개(최대 3개)를 동시에 비교
- [x] 측정 데이터 CSV 내보내기
- [x] 저사양 기기: 프레임당 계산 예산, 무거운 효과 자동 축소

**완료 기준:** 저가형 휴대폰에서 60fps에 가깝게 동작하고, 처음 쓰는 사람이 설명 없이 반응 3개를 발견한다.

### 2단계: 물리 엔진 강화 (2~3개월)

"물리 법칙을 제대로 확인"하는 목표의 핵심입니다. 엔진의 큰 변경은 이 단계에 모읍니다.

- [ ] **칸 단위 질량 도입:** 칸마다 질량을 저장해 질량 보존 법칙을 만족
- [x] **압력 기초:** 닫힌 공간의 PV=nRT(게이뤼삭 법칙 측정 가능), 액체로 이어진 공간은 같은 압력(파스칼), 가루는 기체가 새어 나감, 밀폐 용기 파열, 압력계
- [x] **압력과 끓는점:** 압력솥(높은 압력 → 높은 끓는점), 진공 펌프(상온에서 끓음), 대기압에 찌그러지는 캔, 압력이 필요한 반응(하버 공정)
- [x] **수압·기체 분리:** ρgh 수압(끓는점에 반영), 섞인 기체는 천천히 분리
- [x] **튀는 칸:** 폭발 파편·물보라의 포물선 운동, 섞기 도구
- [x] **고체 덩어리(강체):** 낙하, 부력으로 뜨고 가라앉기, 떨어져 깨짐. 회전·옆으로 미끄러짐은 아직 없음
- [x] **압력 도구:** 피스톤으로 부피 바꾸기(보일 법칙), 펌프로 기체 넣고 빼기, 압력 보기
- [x] **움직이는 피스톤:** 압력 차와 무게로 스스로 움직임(샤를·보일 법칙)
- [ ] **압력파:** 압력이 퍼지는 속도, 충격파
- [ ] **유체 개선:** 칸 단위 속도장 도입으로 소용돌이와 물결 표현
- [ ] **강체 확장:** 공 외에 상자·막대, 회전, 경사면, 도르래, 용수철
- [x] **강체↔유체 양방향:** 공이 물을 밀어내 수면이 오르고 물보라가 튐, 나무 블록·나무 공이 뜸
- [x] **복사열:** 500°C 넘는 물체가 공기와 닿은 면으로 슈테판-볼츠만 법칙(εσT⁴)만큼 열을 잃음
- [x] **전기 분해:** 물 → 수소 + 산소(2:1), 소금물, 도금, 정련, 합선
- [x] **화학 전지와 전구:** 볼타·레몬·다니엘 전지, 전원-전구 회로
- [ ] **전기 회로 심화:** 저항, 전압·전류 표시, 줄 열
- [ ] **성능:** 칸 수가 늘어나면 WebWorker → WebAssembly → WebGPU 순으로 이전

**물리 실험 모드 추가 목록**

| 주제 | 비교할 법칙 |
|---|---|
| 포물선 운동 | 사거리 = v²sin2θ/g |
| 단진자 | T = 2π√(L/g) |
| 용수철 | F = -kx, 에너지 보존 |
| 경사면 | 마찰 계수 측정 |
| 탄성·비탄성 충돌 | 운동량 보존 |
| 뉴턴 냉각 | 지수 감소 곡선 |
| 보일·샤를 법칙 | PV, V/T 일정 |
| 파스칼·아르키메데스 | 수압, 부력 |
| 비중 측정 | 부력으로 물질 판별 |

**완료 기준:** 각 실험의 측정값이 이론값과 정해 둔 오차(예: 5%) 안에 들어오고, 이를 자동 테스트로 계속 확인한다.

### 3단계: 화학 시스템 확장 (2~3개월)

- [x] **물질 확장:** 주기율표 전체, 금속 반응성 계열, 불꽃 반응 색, 앙금, 합금
- [x] **지시약 기초:** 페놀프탈레인, 리트머스 색 변화
- [ ] **몰 단위 반응:** 칸의 물질량을 사용해 화학 양론을 만족 (한계 반응물 개념)
- [x] **용액 시스템(1차):** 칸마다 농도, 묽힘(용질 보존), 끓는점 아래의 증발
- [x] **용액 시스템(2차):** 온도에 따른 용해도, 포화와 재결정, 증발하면 진해짐
- [ ] **용액 시스템(3차):** 서로 다른 물질이 한 칸에 함께 녹은 혼합 용액
- [x] **pH 기초:** 물질별 pH 값, 지시약마다 다른 변색 범위, BTB 추가
- [x] **pH 심화:** 농도에 따라 변하는 pH, 적정 실험(당량점 오차 약 5%)
- [x] **반응 속도(농도):** 묽은 용액은 생성물이 농도만큼 적게 생김
- [x] **반응 속도(온도):** 10°C마다 약 2배
- [x] **착이온과 부동태 기초:** 구리·은-암모니아, 철-싸이오사이안산, 양쪽성 수산화물, 크로뮴산⇄다이크로뮴산, 철·알루미늄·크로뮴의 부동태
- [x] **산화수:** 철과 수증기 → Fe₃O₄, 산화성 산 → 철(III), 아이오딘 → 철(II) 등
- [x] **물질 도감:** 정보 탭에 물질별 설명·성질·함께 반응하는 재료
- [ ] **데이터 검수:** 물성값과 반응식을 교사나 전공자가 확인하고 출처를 기록

**안전 원칙:** 실제로 위험한 물질의 제조법이나 구체적인 합성 조건은 넣지 않습니다. 시뮬레이션은 현상 관찰용이며, 실제 실험을 안내하지 않는다는 문구를 화면에 표시합니다. 특히 나트륨·산·염기 실험에는 "실제로 따라 하지 마세요" 안내를 넣습니다.

### 4단계: 게임 요소 (1~2개월)

- [x] **발견 도감:** 진행률 막대, 못 찾은 반응 이름 힌트
- [x] **도전 과제 기초:** 20개, 완료 이벤트
- [ ] **도전 과제 확장:** "물을 쓰지 않고 불을 꺼라", "1kg 철 공의 낙하 시간을 예측하라" 같은 예측형 과제
- [x] **예측 → 실험 → 비교:** 예측 문제 8개(정답·설명·저장)
- [x] **장치 부품:** 스위치, 밸브, 진공 펌프, 피스톤(켜기·끄기 도구)
- [x] **만든 실험 공유:** 공유 코드(갤러리는 사이트 쪽 기능)

### 작업 원칙: 다른 사이트에 합칠 것을 전제로

앞으로의 작업은 모두 아래를 지킵니다.

- 사이트에 넣는 파일은 `dist/sandlab.js` 하나. 외부 라이브러리·네트워크 요청·`eval` 없음(CSP 통과)
- 전역 이름은 `SandLab` 하나, 화면은 Shadow DOM 안. 사이트 CSS와 서로 영향을 주지 않음(`embed-example.html`로 확인)
- 공개 API(`SandLab.create`가 돌려주는 메서드, 이벤트, `<sand-lab>` 속성)는 바꾸지 않고 늘리기만 함. 바꿔야 하면 `SandLab.version`을 올리고 예전 이름을 별칭으로 남김
- 저장 데이터는 물질 이름으로 저장해 물질 목록이 바뀌어도 복원됨. 형식이 바뀌면 `version`과 변환 함수
- 엔진(`engine.js`)은 화면과 무관하게 유지해 서버·테스트·다른 화면에서도 돌아가게 함
- 화학 판단은 `reactions.js`, 물질은 `materials.js`에 데이터로 둠(나중에 사이트별로 물질 제한·지연 로딩을 하기 쉽게)
- `dist`는 항상 `src`와 같게 유지(배포 때 `sh build.sh --check`로 자동 확인)

### 5단계: 사이트 통합 (대상 사이트가 정해지면 1~2개월)

- [ ] 대상 사이트 기술 스택 확인 후 패키지 형태 결정

- [ ] **학습 기록 연동:** `sandlab:discover` 이벤트를 사이트의 진도·점수와 연결
- [x] 재료 제한 옵션(`materials`, `<sand-lab materials="...">`)
- [ ] **교사 기능:** 특정 실험 배정, 결과 제출(사이트의 계정 기능과 함께)
- [ ] **번들 크기 관리:** 물질·실험 데이터 분리 및 지연 로딩
- [ ] **다국어:** 문자열을 데이터 파일로 분리 (한국어·영어)

- [ ] **접근성:** 키보드만으로 그리기
- [x] **콘텐츠 보안 정책(CSP):** eval·new Function·외부 요청 없음

## 4. 먼저 정해야 할 것

아래 결정에 따라 2단계 이후의 설계가 달라집니다.

1. **사용자가 누구인가요?** 초·중·고 또는 일반인에 따라 화학식 표시 수준과 도전 과제가 달라집니다.
2. **어떤 사이트에 들어가나요?** 기술 스택과 계정 시스템을 알면 5단계 형태가 정해집니다.
3. **학습 도구와 놀이 중 어느 쪽이 우선인가요?** 정확성과 화려함이 충돌할 때 기준이 됩니다. 현재는 정확성을 우선했습니다.
4. **이름과 시각 스타일은 어떻게 할까요?** 참고한 게임의 이름이나 그림을 그대로 쓰지 않도록, 자체 이름("모래 실험실"은 임시 이름)과 스타일이 필요합니다.
